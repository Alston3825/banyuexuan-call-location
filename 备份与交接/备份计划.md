# 每日备份计划

从2026-11-20起，每天洛杉矶时间03:00、09:00、15:00、21:00整理开发进度与交接并运行检查点备份，时区America/Los_Angeles（随夏令时变化）。不是北京时间；如门店采用北京时间，应另调整计划。保留既有每5分钟源码同步，其他项目计划不变。

独立私有仓库：Alston3825/banyuexuan-call-location；中文项目名写入描述。main保存最新安全快照，checkpoint/标签保存四次任务实际执行的版本，Git历史持续保留，本方案不自动删历史。相同内容也可用标签形成检查点，不伪造未执行的时间点。

自动任务先读交接和最新开发记录，补充实际进展，再运行 `python3 tools/backup_checkpoint.py`。同步和检查点共用sync.lock，不并发改镜像；推送非force，失败不登记成功。脚本验证远端main后推送检查点；失败会在自动任务显示，正常静默。状态在本机 ~/.banyuexuan-project-sync/call-checkpoint-status.json，含已确认提交和实际检查时间，不能把旧成功状态当当前成功。

电脑、用户登录会话、Codex和网络须可用；关机时无法承诺四次上传。现有LaunchAgent每5分钟/登录后重试源码同步，下一次自动任务生成新的实际检查点，不补写假的历史执行记录。每周检查状态时间及失败任务；每月从远端独立clone并运行tools/verify_backup.py做恢复抽查。

扫描拒绝疑似私钥/常见令牌、超99MiB文件；关键文件缺失、文件数量减少超过20%、扫描期间内容变化会失败。排除真实配置、数据库、运行上传及模型，保留源码模块内正常的auth/models/data目录。CI配置以文本归档，防止备份触发部署。模式检测不能替代人工去敏审查；新增资料须遵守交接说明的安全边界。

恢复顺序：授权账号clone → 选择main或checkpoint标签 → SHA256校验 → 阅读交接及最新任务 → 安装依赖/软件测试 → 单独取得安全配置和模型 → 经授权在隔离环境恢复数据与现场验证。GitHub账号开启双因素、保留独立恢复方式；本机镜像和GitHub均不能替代生产数据的独立加密灾备。
