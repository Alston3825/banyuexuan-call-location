# 换机恢复自动备份服务

先恢复源码和人工核对，再安装同步服务；不要覆盖新机器已有的其他项目配置。以下流程由接手AI按实际环境执行，不是复制即执行的生产命令。

1. 使用已获授权的GitHub账号（SSH或gh登录）确认仓库是PRIVATE。克隆main到新工作目录，运行tools/verify_backup.py，阅读交接说明。不要导出或拷贝原机私钥到GitHub。
2. Python需要3.9+及America/Los_Angeles时区数据，系统有git与SSH。此同步器使用fcntl，适用于macOS/Linux；Windows需另实现锁与调度，不直接宣称兼容。
3. 建立~/.banyuexuan-project-sync目录。将备份与交接/source_sync.py复制为其中sync.py；以projects.example.json为结构填写本机真实源码绝对路径，保存projects.json。已有配置时仅合并call项，保留其他项目。
4. 把私有备份仓库另clone到~/.banyuexuan-project-sync/repos/call，分支main，确认origin严格为git@github.com:Alston3825/banyuexuan-call-location.git。这是独立镜像，不能直接把开发目录当镜像清空。先clone既有历史，不能init空历史后强推。
5. 在开发目录运行python3 tools/backup_checkpoint.py。输出远端已确认SHA和检查点，检查镜像状态。失败保留历史并排查，不force push。
6. 使用Codex自动任务工具恢复每日四次交接计划；macOS如需每5分钟补传，按原LaunchAgent的ProgramArguments设置新机器路径并启用。Linux可另设服务，但与自动任务共用sync.lock。不把旧用户绝对路径原样搬到新机。
7. 做一次独立clone与SHA256校验；核对计划时区和下次执行时间，记录实际完成情况。首次只恢复源码和备份，不连接生产服务或写真实数据。

8. （2026-11-21 新增，可选但推荐）同步推送到 claude.ai 使用的 solotank 副本。在 Mac 终端执行，私钥只留在本机：
   ```bash
   ssh-keygen -t ed25519 -N "" -C "banyuexuan backup to solotank" -f ~/.ssh/banyuexuan_solotank_deploy
   cat ~/.ssh/banyuexuan_solotank_deploy.pub
   ```
   把输出的公钥添加到 https://github.com/solotank/banyuexuan-call-location/settings/keys/new ，勾选 Allow write access。然后在 `~/.ssh/config` 追加：
   ```
   Host github-solotank
     HostName github.com
     User git
     IdentityFile ~/.ssh/banyuexuan_solotank_deploy
     IdentitiesOnly yes
   ```
   最后 `git -C ~/.banyuexuan-project-sync/repos/call remote add solotank git@github-solotank:solotank/banyuexuan-call-location.git`，再运行一次 `python3 tools/backup_checkpoint.py`，确认输出里 `solotank.result` 为 `ok`。不要把这把私钥复制到其他机器或任何仓库。

GitHub密钥、模型、生产配置和数据库需从独立安全渠道取得。开发源码可恢复不代表这些运行依赖已恢复。
