# 数字孪生定位对接：处理结果与数据契约

日期：2026-11-20（America/Los_Angeles）。开发入口：development/bycall。依据用户提供的“伴月轩数字孪生高新店/docs/定位接入/呼叫定位项目对接核验.md”逐项核验；文档中的现场操作顺序仅作为资料，没有据此改信标、写现场参数或发布新程序。数字孪生项目原文件未修改。

## 对接缺口处理

| 核验项 | 本项目处理 | 仍需现场验证 |
| --- | --- | --- |
| 熄屏扫描使用空过滤器 | 改为 manufacturer 0x004C 的非空 02 15 前缀过滤；配置UUID时进一步精确过滤；回调再次验证；非法UUID拒绝启动 | Android9实表亮屏/熄屏、厂家白名单与电量 |
| 扫描失败不可见 | 权限、系统定位关闭、蓝牙关闭、扫描器不可用、UUID错误、启动/停止异常、onScanFailed均记录状态；上报错误码，后台手表行可见 | 实物权限和蓝牙开关操作 |
| 空窗口不发、旧位置保留 | 空窗口照常发LOCATION_REPORT；未知/弱信号/扫描失败不沿用旧窗口；主机持久化当前报告，与移动历史分开 | 一表一信标、移出覆盖范围、断网与主机重启 |
| 缺样本诊断 | 原readings兼容增加sample_count/age_ms；报告增加sampled_at、report_interval_s、scan_status、scan_error_code、observation_source、staff | 真实射频采样与时间设置 |
| 区域定位误作精确坐标 | 提供区域级只读投影，明确fresh/unknown/stale；coordinates始终null | 高新店24F真实区域/房间/楼层与3D锚点映射 |

默认仍为每10秒扫描2秒，不改为草案5/15秒。新增字段均在原MQTT信封和原主题内，不建立平行设备协议、不改ACL主题。过滤的依据见 [Android BluetoothLeScanner](https://developer.android.com/reference/android/bluetooth/le/BluetoothLeScanner#startScan(java.util.List%3Candroid.bluetooth.le.ScanFilter%3E,%20android.bluetooth.le.ScanSettings,%20android.bluetooth.le.ScanCallback)) 与 [ScanFilter.Builder](https://developer.android.com/reference/android/bluetooth/le/ScanFilter.Builder#setManufacturerData(int,%20byte[],%20byte[]))。正确使用过滤器不等于厂家设备已通过熄屏验收。

## 当前状态与历史记录

`location_current` 按门店/手表记录最新报告、绑定、接收时间、诊断和最后一次有效位置；`locations` 仍为区域变化历史，不能将其最后一行直接当当前位置。

- **fresh**：当前报告包含已登记且有效的实际观测，设备在线、绑定匹配，未超过有效期；报告里没有出现的旧信标不能仅凭滑动窗口继续胜出。
- **unknown**：从未观测、空窗口、未登记信标、信号太弱、扫描错误、样本过旧、模拟数据、绑定改变、空间映射改变或未佩戴。当前room/area/floor为null。
- **stale**：报告过期、设备离线或主机重启后尚未收到本进程新观测。当前room/area/floor为null。只在管理接口单独保留last_known历史证据，3D接口不返回它。

有效期为max(30, report_interval_s×3)秒，上限180秒；默认10秒上报对应30秒。若提供样本age_ms，过期判断包括样本在终端缓存的时长。sampled_at是诊断采样时刻，不用手机墙上时钟独自证明新鲜度。旧载荷无新字段仍可接收，但其时间信息仅能追溯到主机收到报告时，不能声称补齐了历史采样精度。

心跳只能证明设备连接，不刷新位置时间；主机重启不能凭磁盘旧记录恢复成fresh；换表/换人不展示前一个佩戴者的位置与体征。新版手表上报staff，主机拒绝与当前绑定不一致的报告；不带staff的旧APK仍兼容，应尽快升级。

`/nurses/locations`与`/station/snapshot`已按上述当前状态输出；旧区域历史仅供追溯。后台手表列表显示蓝牙与定位状态。大屏未知/过期时不继续显示旧位置名称。

## 给数字孪生后端的只读接口

`GET /integration/twin/locations`

- 服务端配置独立`BYCALL_TWIN_KEY`，调用时使用`X-Api-Key`请求头；未配置返回503，错误密钥返回401。不得复用主机管理员或换表密钥；相同值会拒绝启用本接口。
- 此密钥只可读本投影，不能访问终端设置、发布APK、备份或其他管理接口。不要写入静态HTML、前端脚本、URL或日志。
- 数字孪生服务端保存密钥并代理请求，再裁剪返回浏览器。默认没有开放跨站浏览器CORS。
- 仅上传代码包不会给旧容器自动添加环境变量。实际启用需在现场安全配置独立密钥并按既定发布方式将其注入host容器；本轮没有执行。
- `schema=bycall.location.v1`；根节点store_id、server_time、items。items仅含当前绑定人员；没有姓名、体征、语音、客户呼叫文本、MAC或UUID。

示例是虚构数据，不代表高新店的真实编号或位置：

```json
{
  "schema": "bycall.location.v1",
  "store_id": "example-store",
  "server_time": "2026-11-20T10:00:00+00:00",
  "items": [{
    "watch": "example-watch", "staff": "example-staff", "online": true,
    "location_status": "fresh", "location_reason": null,
    "zone_id": "24-1", "room": null, "area": "示例公共区域", "floor": "示例楼层",
    "precision": "area", "coordinates": null,
    "received_at": "2026-11-20T09:59:57+00:00", "observed_at": null,
    "age_seconds": 3, "stale_after_seconds": 30
  }]
}
```

`zone_id`为当前有效信标标识，和store_id一起作为区域映射键；区域名称可以改名，不能用名称替代稳定映射键。公共区域room可以为null。unknown/stale时zone_id及当前区域字段均为null，不把最后已知区域渲染成实时位置。3D可在确认的区域展示锚点上画人形标记；该锚点是模型展示点，不是实测连续坐标。不要沿路径插值并冒称人员实际轨迹。

推荐数字孪生后端2–5秒拉取一次，断流或服务错误时自行标记数据不可用，不永久保留上次fresh。floor保留真实配置值（如“24”或“24F”），两项目必须明确映射；不能把演示16层替换成高新店24F。配置UUID为空仅适合台架核验，同店Major-Minor身份隔离需要实物UUID与手表筛选一致。

## 下一步现场联调

1. 只在本机私有台账核对实物UUID、Major/Minor、实际房间/公共区域和楼层；不把身份或凭据写入公开文档。
2. 使用统一后台配置单表UUID及扫描参数，整体替换信标表前完整保留已有条目。没有授权时不改信标实物。
3. 主机和手表成套升级后，一表一信标验证亮屏/熄屏、扫描错误码、空观测、移出覆盖与恢复；平板无需因本协议扩展强制重装。
4. 安全配置数字孪生只读密钥，确认高新店区域锚点映射，再实测fresh→unknown/stale→fresh及换表。当前未连接数字孪生服务器或N100执行这些动作。

软件测试不能替代信标射频、现场地图、厂家权限与10小时续航验收。验证结果见根目录当前开发任务最新条目。
