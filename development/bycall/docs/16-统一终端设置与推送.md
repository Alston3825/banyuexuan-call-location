# 统一终端设置与推送

日期：2026-11-20（America/Los_Angeles）。基线：用户桌面 bycall 最新源码的独立开发副本，见 ../BASELINE.md。本轮没有操作 N100、真实设备或业务库。

## 使用入口

升级本版本主机后，浏览器打开 `http://主机IP:8100/admin/terminals`，或点击护士站大屏的“终端后台”。输入现有主机管理员密钥（BYCALL_API_KEY），选择手表、客房平板或护士站大屏，勾选设备及需要修改的字段，点击“保存并推送”。未勾选字段保持原样；页面当前值为已保存的目标配置或建议默认值，并非对所有旧设备实际本地值的读取。大屏/终端仅应用本次保存过的字段。

状态：未配置、等待终端接收、正在验证连接、已应用、应用失败/已回退。后台保存成功不等于设备已应用；必须查看对应版本回执。离线设备恢复后由心跳补发。旧版 APK 无配置回执能力，后台显示“尚未确认新版能力”，不能将其当作应用成功。

一次性准备：首次联网仍需在终端本地填写设备身份、连接地址和设备密码。主机需登记真实门店/设备并准备 MQTT ACL。之后只要终端已连通，即可从后台批量修改下列参数。新增功能不要求增加 MQTT ACL 主题。

## 参数范围

| 终端 | 支持参数 |
| --- | --- |
| 手表 | MQTT 主机/端口、HTTP 接口地址；心跳10–30秒；定位上报7–60秒；信标UUID筛选；扫描时长/周期；Wi-Fi和CPU唤醒保持；求助长按500–5000毫秒；同事语音5–30秒；快捷回复 |
| 平板 | MQTT 主机/端口、HTTP 接口地址；房间显示名；心跳10–30秒；语音留言按钮开关 |
| 大屏 | 标题、声音开关、已结束呼叫展示时段、未接单标红时间、手表位置40–120个、页面字号比例80–140% |

手表扫描周期最少7秒，扫描时长必须小于周期；位置上报独立调度，两个周期需结合真实手表与信标测试，配置成功并不证明扫描权限已授予或信标能被收到。上报间隔不是房间判定保证时延。

连接地址变更会保留原配置，使用新 MQTT 会话的主机回执、同门店 `/health` HTTP 检查共同确认；90秒内未确认则整批回退（设备休眠/系统强停时以恢复运行后检查为准）。回退状态与版本保留，主机不会在每次心跳无限重试同一失败版本；修正后再次保存会产生新版本。更改连接前必须准备目标服务的同门店配置、相同设备账号和配置记录；不提供跨门店/跨主机迁移服务。

设备号、门店号、房间绑定、MQTT密码、API密钥不通过此通道修改。这里的房间显示名不改变呼叫归属。平板呼叫按钮与岗位路由继续使用原大屏入口，避免和本配置协议混用。

## 蓝牙信标

手表页整合：本店UUID筛选、扫描参数、定位上报和全店信标房间对应表。实物UUID应与手表筛选一致，每颗信标的 Major-Minor 唯一，例如16-1601。表中登记 Major、Minor、房间、区域名称；走廊/公共区域可选择空房间并填写楼层，不会据此自动确认进入客房。

对应表保存后主机立即更新定位器并清除旧判断窗口，持久化在独立配置表中，重启恢复；有本地对应表时，定位报告优先使用它。保存的是整个表，需核对后确认替换。历史 bcn-* 演示编号不是实物 Major-Minor，页面明确提示不会自动转换。

本功能不改写信标实物UUID/Major/Minor/发射功率/广播周期。现有资料仅说明 BeaconSET 配置操作，未提供经确认的蓝牙写入协议；上述实物参数仍通过 BeaconSET 设置。

## 协议与存储

- SQLite：terminal_settings（按门店、终端类型、设备隔离的期望值与回执）；terminal_revisions（时间、目标设备、修改字段）；terminal_beacons（全店对应表及版本）。不保存账号密码。
- 管理接口：GET /admin/terminal-config；PUT /admin/terminal-config/{watch|tablet|station}，请求 targets/settings/expected；GET/PUT /admin/beacons。需主机管理员密钥，换表密钥无权访问；主机未配置管理员密钥时拒绝远程管理。
- 批量保存使用一个事务和每设备 expected 乐观锁，任一版本冲突或参数错误则整批拒绝，409时刷新重试。未知设备、未知参数和身份字段均拒绝。
- 安卓下行：reply/{device} 上 TERMINAL_CONFIG，含 kind/device/revision/settings；无 retained 依赖。终端先校验并原子保存，重复版本不重复应用；心跳携 terminal_config_v / terminal_revision / terminal_result / terminal_session，主机仅接受目标版本回执；新网络确认使用对应会话的 TERMINAL_CONFIRM。
- 新消息复用旧有每设备 reply 订阅和 heartbeat 发布，主机校验主题设备与信封设备一致。
- 浏览器大屏：独立稳定的 station-* 编号（同浏览器配置共享），带现有大屏密钥进行20秒长轮询；保存后唤醒等待，应用后HTTP回执；保留原2秒业务数据轮询。大屏先连接主机才出现在后台。清除浏览器存储会成为新大屏编号。
- Android持久化配置不随换表/清除个人会话丢失；WATCH_BIND中的基础策略与本机远程覆盖合并，重连不把已保存的远程值冲掉。连接重建保留平板当前呼叫状态和待发队列。
- 浏览器声音受用户手势限制：后台启用声音不等于浏览器已经允许播放，首次仍需点击“启用声音”。

## 验证与现场验收

软件验证结果见项目根目录 docs/当前开发任务.md 的2026-11-20条目。

现场需成套升级主机和两端APK（同签名才能覆盖安装），刷新大屏，然后按以下顺序验收：

1. 单表修改UUID与扫描周期，看目标版本变“已应用”，重启手表确认保留；同时验证原有接单/语音/换表。
2. 断网保存配置，恢复网络确认补发；批量不同设备确认只修改勾选项。
3. 平板改显示名、关闭留言按钮，呼叫和回执应继续正常；恢复留言后验证录音上传。
4. 大屏改标题/40格/声音，验证自动更新与版本回执；首次声音手势授权、显示器分辨率需现场检查。
5. 测试表改成一个不可达地址，确认超时回退并显示失败；修正重发应成功，期间留意客户呼叫不丢。
6. 信标实物用BeaconSET配置后登记对应表，做两房/走廊/关门/熄屏测试，核对不串房、不误到场。再做10小时续航与漫游测试。

实机推送、断线回退、休眠、厂家权限和真实信标效果仍待现场验收；软件测试不替代这些验收。

本轮最终结果：136项后端回归、8项Android配置生命周期测试均通过；两端debug构建和lint通过（Error=0、NewApi=0）；浏览器验证配置自动应用回执、标题更新及1280×720默认40格可见。全部使用临时虚构数据，未做实物安装。
