## 2026-11-10 MQTT 账号密码与按设备权限
- 每台设备一个 MQTT 账号:用户名 = device_id(如 `tab-1601`、`w-01`),另有 `host`(主机)和 `station`(预留)。`host/tools/gen_mqtt_auth.py` 按门店配置生成 `passwd`(Mosquitto `$7$` PBKDF2 哈希)、`acl` 和 `credentials.json`(明文密码,仅用于给设备配置,权限 600,已 gitignore)。重跑不会改已有密码,新增设备只多出新账号。
- 权限:平板只能发自己房间的呼叫主题和自己的心跳/状态,只收自己房间反馈;手表只能发自己的心跳/位置/体征/状态,只收发给自己的派单;主机全权。
- 主机额外校验:心跳/位置/体征/状态主题里的设备名必须等于消息里的 device_id,否则拒绝(`topic_device_mismatch`)。
- 已知缺口:`ack/{call_id}` 主题里没有设备名,无法按设备限制,持有有效账号的设备理论上可冒用他人 device_id 接单;主机用呼叫归属校验限制了破坏范围(只有接单人能完成/到场),彻底解决需要 MQTT 5 或在消息里加签名,暂不做。传输未加密(店内局域网明文),如需 TLS 另行规划。
- 验证:真实 Mosquitto 2.1.2 上 `tools/mqtt_acl_check.py` 17 项全过(匿名/错密码被拒、越权发布被丢弃、越权订阅收不到);主机带账号连接正常收到平板呼叫;主机测试 50 个通过;平板和手表 APK 重新编译通过。安卓端新增设置项 `mqtt_password`(账号固定为 device_id,密码留空则匿名,仅开发用)。**安卓端带密码连接尚未在模拟器上实测。**
- 上线步骤:1) `python tools/gen_mqtt_auth.py --config <门店配置> --out mosquitto/auth`;2) `.env` 设 `MQ_CONF=mosquitto.prod.conf`、`MQTT_USER=host`、`MQTT_PASSWORD=<credentials.json 里 host 的密码>`;3) 每台设备在设置里填对应密码;4) 运行 `tools/mqtt_acl_check.py` 复核。

## 2026-11-10 数据库每日备份与恢复
- 主机内置每日备份:默认每天 3 点(`BYCALL_BACKUP_HOUR`)备份 SQLite 到 `BYCALL_BACKUP_DIR`,保留 7 天(`BYCALL_BACKUP_KEEP_DAYS`)。首次启动 1 分钟后补一份;停机错过当天时间,开机后当天补一次。备份失败只记日志,不影响呼叫。
- 实现:SQLite 在线备份接口(主机运行中也一致,兼容 WAL)→ 完整性检查 → gzip → 写完才改名出现。过期清理按文件时间,**永远保留最新一份**,避免时钟错误或备份连续失败时把最后一份好备份删光。
- 命令行 `host/tools/backup.py`:`backup`(手动备份)、`list`、`restore`。恢复必须先停主机、加 `--yes`;会先校验备份可读且完整,通过后才替换,原数据库不删除而是改名为 `host.db.before-restore-时间` 留存,并一并处理残留的 -wal/-shm。
- **重要**:默认备份和数据库在同一块盘,只能防误操作,防不了坏盘。上线时 `BACKUP_PATH` 必须指到另一块盘/NAS/U 盘(或定期拷走),这个要在部署时确认。
- 未包含:语音留言文件(本来只保留 7 天,不备份)、Mosquitto 账号文件(可由 `gen_mqtt_auth.py` 重新生成,但 `credentials.json` 要另存,丢了所有设备要重新配密码)、配置文件(在代码库里)。
- 验证:测试 54 个通过(含备份时数据库正在使用、恢复回滚、过期清理、损坏备份被拒且原库不动);真实主机上手动备份、自动备份、停机后恢复(2 条呼叫的库恢复到备份时的 1 条)均正常。未做:跨机自动拷贝、备份失败告警(目前只在日志)。

## 2026-11-13 手表崩溃原因找到并修复
- 崩溃记录显示:`NoSuchMethodError: PackageInfo.getLongVersionCode()`(Updater.installedCode)。这个方法要 Android 9(API 28),手表系统更旧(最低支持 API 26),更新检查一启动就崩;且后台线程里只 catch 了 Exception,Error 没接住,所以整个应用崩溃。主界面每次打开都会触发检查,所以"打开就闪退",而后台服务不受影响。

- 教训:以后发布前跑 `./gradlew :watch:lintDebug :tablet:lintDebug`(NewApi 必须为 0),模拟器是新系统看不出这类问题。
