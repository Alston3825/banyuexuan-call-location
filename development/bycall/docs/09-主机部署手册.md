# 呼叫主机部署手册(N150 迷你工控主机)

**主机硬件(已定)**:Intel N150 / 16 GB DDR4 / 512 GB M.2 硬盘 / 迷你工控机(下文统称“N150”)。
**主机 IP(已定)**:`192.168.1.108`(下文的 `主机IP` 都指它)。
**系统**:Ubuntu Server 24.04 LTS(x86_64)。**程序**:Docker 容器(主机服务 + Mosquitto),不需要在主机上装 Python。

> **状态**:镜像构建、容器启动、健康检查、备份、账号生成已在本机(Mac,Docker)实测通过;**本手册的操作系统安装、BIOS、网络、防火墙、云备份配置等步骤尚未在真实 N150 主机上走过**,第一次部署请边做边核对,发现不对的地方告诉我,我来改手册和脚本。

## 1. 这台硬件够不够

| 项目 | 判断 | 依据 |
|---|---|---|
| CPU / 内存 | 绰绰有余 | 两家店最大 30–34 房、约 35 块手表;我已用 30 房并发测试通过(内存模拟);N150 的实际占用待样机阶段实测,清单 N10 |
| 硬盘 512 GB | 足够 | 估算(待实测):呼叫记录、位置轨迹、心率每天合计几十 MB;语音留言只留 7 天;备份压缩后很小。预计一年远低于 50 GB |
| 网口 | 单千兆网口即可 | 必须**有线**接路由器/交换机,不要用主机 Wi‑Fi |
| 断电 | 最大风险 | 迷你工控机没有电池;建议配 UPS(≥600 VA,断电后能撑 10–30 分钟),至少要在 BIOS 设“来电自启” |

**还需要采购**:
1. **云存储账号**(用于异地备份):任意 S3 兼容对象存储(阿里云 OSS、腾讯云 COS、华为云 OBS、七牛等),建一个桶和一个只能读写该桶的子账号密钥。备份在主机上**先加密再上传**。(可选:再加一块 USB 硬盘做第二份本机备份。)
2. **UPS**(强烈建议)。
3. 做系统安装盘用的 U 盘(≥ 8 GB)。

| Boot Mode | UEFI | |
| Secure Boot | 保持默认即可 | Ubuntu 支持 |
| 睡眠/休眠/节能关机 | 关闭 | 不能睡眠 |
| 系统时间 | 改成准确的北京时间 | 班次、计时、备份都依赖时间 |

## 3. 安装系统

1. 在另一台电脑下载 **Ubuntu Server 24.04 LTS**(x86_64 / amd64)ISO,用 balenaEtcher 等写入 U 盘。
2. U 盘插主机、网线接路由器,开机选 U 盘启动。
3. 安装选项:语言 English(便于排查故障)、整盘安装(用 M.2 全部)、**勾选安装 OpenSSH server**、不安装额外组件(Docker 后面脚本装)。
4. 记下你设的**用户名和密码**(用于远程登录主机)。装好重启,拔 U 盘。

---

## 4. 固定 IP

设备(平板、手表、大屏)都靠主机 IP 连接,**IP 绝不能变**。二选一:
- **推荐**:在路由器里按主机网卡 MAC 地址做“静态 IP 绑定/DHCP 保留”(本店定为 `192.168.1.108`),主机本身保持 DHCP。
- 或在主机上用 netplan 写固定 IP(`/etc/netplan/*.yaml`,`dhcp4: false` + addresses/routes/nameservers,`sudo netplan apply`)。

记下这个 IP,后面叫它 `主机IP`。

## 5. 安装主机程序

### 5.0 一键安装(推荐,2026-11-17 新增)

系统装好、网线接好、能联网后,只需要三步:

1. **把程序拷到主机**(在 Mac 上,项目根目录运行;`用户名`/`主机IP` 换成第 3、4 步记下的):
   ```sh
   scp -r host 用户名@192.168.1.108:/tmp/
   ```
   (没有网络连通时,用 U 盘把 `host` 文件夹拷过去也可以。)
2. **登录主机**:`ssh 用户名@192.168.1.108`,然后:
   ```sh
   sudo mkdir -p /opt/bycall && sudo rm -rf /opt/bycall/host && sudo mv /tmp/host /opt/bycall/host
   cd /opt/bycall/host
   sudo bash deploy/setup-host.sh --lan 192.168.1.0/24 --ip 192.168.1.108
   ```
3. 等它显示 **“健康检查:{"ok":true …}”** 和一份“安装信息”(大屏地址、备份页、更新页、设备该填什么)。完成。

脚本会自动做完下面第 5~8 步的事:初始化系统(第一次)、生成全部设备的 MQTT 账号、生成 `.env`(主机 IP、随机大屏密钥、host 的 MQTT 密码)、构建镜像并启动、等到服务就绪。**可以重复运行**:改了门店配置、增减设备后再运行一次即可,已有的密钥和设备密码不会变。

- 主机**不能联网**时:在 Mac 上 `cd host && ./build_host.sh` 打出 `dist/bycall-host-amd64.tar.gz`,一起拷过去,运行时加 `--image /tmp/bycall-host-amd64.tar.gz`(Mosquitto 镜像仍需联网下载一次)。
- IP 自动识别不对时,加 `--ip 192.168.1.108` 指定。
- 云备份(第 6 步)仍需手动把 `CLOUD_*` 填进 `.env`,填完 `sudo docker compose up -d` 生效;没配时脚本会提醒。
- 正式门店配置:放 `config/store.json` 后再运行一次脚本,会自动切换(见第 7 步说明)。

> 状态:脚本在开发机上测过“生成账号 + 生成 .env + 重复运行不覆盖”;**Docker 启动部分还没在真实 N150 上跑过**,第一次请把屏幕输出留着,有报错发给我。

以下 5.1 及第 7、8 步是手动方式,一键安装失败时按它逐步排查。

### 5.1 手动初始化主机(联网时做一次)

把 `host/` 整个文件夹拷到主机的 `/opt/bycall/host`(U 盘或 `scp -r host 用户名@主机IP:/tmp/` 后 `sudo mkdir -p /opt/bycall && sudo mv /tmp/host /opt/bycall/host`)。然后:

```sh
cd /opt/bycall/host
sudo bash deploy/install-ubuntu.sh --lan 192.168.1.0/24    # 换成你们店内的真实网段
```

脚本会:设时区为上海、装 Docker 和 Compose、装时间同步和硬盘健康监测、设防火墙(SSH 只对局域网开放)、限制系统日志体积。可重复运行。

> **时间同步**:主机断外网后,时钟靠主板电池和 chrony 对时。长期不联网,时间可能慢慢走偏:每月核对一次(大屏/`date`),或让路由器提供局域网对时。

## 6. 准备云备份(推荐)

1. 在云厂商控制台建一个**私有**桶(不要公开读),区域选离店近的;建一个只授权该桶读写的子账号,记下 `Endpoint`(如 `https://oss-cn-hangzhou.aliyuncs.com`)、桶名、`AccessKey`、`SecretKey`。两家店可共用一个桶,用不同的 `CLOUD_PREFIX`(如 `bycall/gaoxin/`、`bycall/zaoyuan/`)。
2. 想好一个**加密口令**(随机长字符串,例如 24 位以上)。⚠ **抄录两份存放在不同地方**:数据在上传前用它加密,**口令丢了,云端的备份谁也打不开**(包括我们)。
3. 这些在第 7 步写进 `.env`。不配置云存储时,系统只做本机备份(与数据库同一块盘,只能防误操作,防不了坏盘),大屏不会提醒——所以**正式使用前务必配好**。
4. 默认每天 03:00、09:00、15:00、21:00(门店时间)各备份一次:先做本机备份,再加密上传;外网断了只会上传失败并自动重试,不影响本机备份和呼叫。可在管理页修改时段和保留天数(本机默认 7 天,云端默认 30 天,最新一份永远保留)。
5. (可选)再插一块 USB 硬盘做第二份本机备份:`lsblk -f` 找到盘,`sudo mkfs.ext4 -L bycallbak /dev/sdX1`(⚠ 清空该盘,确认设备名),建 `/mnt/backup`,`/etc/fstab` 加 `LABEL=bycallbak /mnt/backup ext4 defaults,nofail,x-systemd.device-timeout=5 0 2`,`.env` 设 `BACKUP_PATH=/mnt/backup/bycall`。

## 7. 生成 MQTT 账号并写配置

```sh
cd /opt/bycall/host
mkdir -p config
cp .env.example .env && chmod 600 .env

# 生成每台设备的账号和权限(主机只需 Docker,不用装 Python)
sudo docker compose run --rm -T -v "$PWD/mosquitto/auth:/out" host \
  python tools/gen_mqtt_auth.py --config /app/bycall/custom/banyuexuan/demo_pilot.json --out /out
sudo cat mosquitto/auth/credentials.json     # 每台设备的密码都在这里
```

> ⚠ **`credentials.json` 另存两份**(例如抄录、U 盘),**不要丢**:丢了所有平板和手表都要重新配密码。
> ⚠ 上面用的是**演示配置**(虚构的 2 个房间)。正式使用前要换成真实门店配置:把真实房间/平板/信标/护士写进 `config/store.json`(格式同 `demo_pilot.json`),并把 `--config` 换成 `/config/store.json`,在 `.env` 里设 `BYCALL_CONFIG=/config/store.json`;接上伴月轩管理系统后这些由管理系统同步。设备增减后重新运行生成命令,原有设备的密码不变。

编辑 `.env`(`nano .env`):`BIND_IP`(主机 IP)、`BYCALL_API_KEY`(随机长字符串)、`MQTT_PASSWORD`(填 credentials.json 里 **host** 的密码)、云备份的 `CLOUD_ENDPOINT / CLOUD_BUCKET / CLOUD_PREFIX / CLOUD_ACCESS_KEY / CLOUD_SECRET_KEY / CLOUD_PASSPHRASE`(见 `.env.example`),`MQ_CONF=mosquitto.prod.conf` 保持不变。

## 8. 启动与验证

```sh
cd /opt/bycall/host
sudo docker compose up -d --build        # 第一次需要联网下载基础镜像和依赖,几分钟
sudo docker compose ps                   # host 应显示 (healthy),mosquitto 为 Up
curl http://主机IP:8100/health           # 应返回 {"ok":true,...}
```

然后:

1. 护士站电脑浏览器打开 `http://主机IP:8100/station?key=<BYCALL_API_KEY>`,能看到大屏(提示“备份 无”属正常,启动 1 分钟后会自动做第一份备份)。
2. 复核 MQTT 安全:`sudo docker compose run --rm -T --network host -v "$PWD/mosquitto/auth:/out:ro" host python tools/mqtt_acl_check.py 127.0.0.1 /out/credentials.json`,应输出 `ALL OK`。
3. 每台平板/手表在“设置”里填:主机 IP、门店号、设备号、`mqtt_password`(该设备在 credentials.json 里的密码)、`api_base=http://主机IP:8100`、`api_key`。

> 机器通电后 Docker 与两个容器会**自动启动**(compose 已设 `restart: unless-stopped`,脚本已设 Docker 开机自启)。

## 9. 日常运维

| 要做什么 | 命令(在 `/opt/bycall/host`) |
|---|---|
| 看运行状态 | `sudo docker compose ps` |
| 看日志(最近 200 行) | `sudo docker compose logs --tail 200 host` |
| 重启服务 | `sudo docker compose restart` |
| 更新程序 | 替换 `bycall/` 等文件后 `sudo docker compose up -d --build` |
| 手动备份一次 | `sudo docker compose exec -T host python tools/backup.py backup --db /data/host.db --dest /backups` |
| 备份管理页 | 浏览器打开 `http://主机IP:8100/backup?key=<BYCALL_API_KEY>`:看最近备份/上传状态、改备份时段和保留天数、立即备份、从本机或云端恢复 |
| 恢复备份 | **推荐在管理页操作**(选一份备份→输入“恢复”确认→主机自动重启并换入,约 20 秒;原数据库改名保留在 `data/host/` 下)。命令行方式(仅本机文件):`sudo docker compose stop host` → `sudo docker compose run --rm -T host python tools/backup.py restore --db /data/host.db --dest /backups --yes` → `sudo docker compose start host` |
| 硬盘健康 | `sudo smartctl -H /dev/nvme0n1` |
| 磁盘占用 | `df -h /`(大屏顶部也显示磁盘余量) |

自动备份:默认每天 4 次(03/09/15/21 点),本机 + 加密云端;本机备份失败或超过 36 小时没有新备份、云端上传连续失败超过 6 小时、或没设加密口令,大屏都会出现橙色提醒并响提示音。

## 10. 断电、故障怎么办

| 情况 | 处理 |
|---|---|
| 突然断电 | 来电后主机自动开机、服务自动起来,设备 2 分钟内自动重连;未处理完的呼叫会补发给手表。恢复后到大屏确认一切正常,查数据库有没有报错 |
| 大屏出现“全部手表/平板失联” | 先查路由器/交换机/AP 是否断电,再查主机网线 |
| 主机连不上了 | 接显示器键盘看是否开机;`sudo docker compose ps`;`sudo journalctl -p err -b` 看系统错误 |
| 主机硬盘坏了 | 换盘重装系统 → 重做第 5–8 步(装好 Docker 并启动主机后,打开管理页,从**云端**选最新备份恢复;`credentials.json`、`.env`(含云备份口令)要有,否则全部设备重配密码、云备份打不开) |
| 云备份连续失败 | 大屏会提醒;查外网、云账号欠费/密钥过期;管理页看具体原因。本机备份不受影响 |

## 11. 安全注意

- 主机只放在店内局域网,**路由器不要把 1883、8100 端口映射到外网**。
- `.env`、`credentials.json` 里有密钥,不要发微信/邮件;大屏密钥只给护士站电脑。
- Docker 发布的端口不受 ufw 防火墙管理,所以靠 `.env` 里的 `BIND_IP`(只绑局域网网卡)和路由器不映射外网来保证。
- 主机登录密码要强;SSH 不对外网开放。
- 系统更新:建议每 1–2 个月联网时 `sudo apt update && sudo apt upgrade`,**选业务低峰期**,更新内核后需要重启(重启约 1 分钟,期间呼叫不可用)。
- 传输未加密(局域网明文),如需加密需另行规划。

## 13. 主机装的是 Ubuntu 桌面版 / 临时用主机自带显示器当大屏(2026-11-17)

N150 实际装的是 **Ubuntu 24.04 桌面版**,安装步骤与服务器版相同(一键安装脚本两种都支持),区别:
- 桌面版默认**没有 SSH**。要从 Mac 远程拷文件/登录,先在 N150 的终端里装:`sudo apt install -y openssh-server`;或者直接用 U 盘把 `host` 文件夹拷到 N150。
- 桌面版默认闲置会**自动休眠**,休眠后整套呼叫系统停止。下面的大屏脚本会把休眠彻底关掉;不用大屏也请运行 `sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target`。

**临时把主机接的显示器当护士站大屏**(先按第 5 步装好主机程序):
```sh
cd /opt/bycall/host
sudo bash deploy/setup-kiosk.sh
sudo reboot
```
开机后自动登录、全屏打开大屏,声音提醒自动开启,浏览器意外关掉 3 秒后自动重开;不黑屏、不锁屏、不休眠。
- 临时退出全屏:Alt+F4(3 秒后会重开);彻底取消:`sudo bash deploy/setup-kiosk.sh --remove` 后重启。
- 主机兼做大屏会多占约 0.5–1 GB 内存,N150/16G 足够;正式使用建议大屏放在护士站电脑/平板上(浏览器打开大屏地址即可)。

## 14. 以后怎么更新(一键推送,不再拷文件)(2026-11-17)

**一次性准备(最后一次拷文件)**:把新的 `host` 文件夹覆盖到主机上,再运行一次安装脚本(依赖已缓存,几分钟):
```sh
sudo cp -r ~/桌面/bycall/host/. /opt/bycall/host/      # 覆盖程序文件;.env、设备密码、数据库、门店配置都不会被动到
cd /opt/bycall/host && sudo bash deploy/setup-host.sh --lan 192.168.1.0/24 --ip 192.168.1.108
```

**以后每次修改后**,在 Mac 上项目目录运行一条命令(第一次会问一次主机密钥并记住):
```sh
./publish.sh 192.168.1.108 "这次改了什么"            # 全部:平板 + 手表 + 主机
./publish.sh 192.168.1.108 "修大屏" host              # 只发布主机
./publish.sh 192.168.1.108 "修手表" apps              # 只发布平板和手表
```
- **平板、手表**:马上弹出“发现新版本”(不在线的设备上线后 10 分钟内也会提示)。手表点蓝色方块;平板由工作人员**长按**橙色提示条;系统再确认一次“更新”。
- **主机**:代码推送后存为“待升级”,大屏顶部出现橙色“主机有新版本”提示条 → 点它(或右上角 ⚙ 设置)→“立即升级主机”。约 10–30 秒,期间大屏短暂断开、设备自动重连;**升级失败自动换回旧版本**。升级成功后**大屏自动刷新成新版**。也可以在 `http://192.168.1.108:8200` 升级。
- 主机升级只替换代码(几百 KB),不需要联网;只有 `requirements.txt`(Python 依赖)变了才需要联网下载。
- 改了 `docker-compose.yml`、`deploy/` 下的脚本、Mosquitto 配置或更新器本身时,仍需按上面“一次性准备”拷一次并运行 setup-host.sh(很少发生,改动说明里会注明)。

**设置按钮**:平板标题右边“⚙ 设置”(需输入设置密码,默认 `8888`,可在设置里改,留空 = 不要密码);手表首页底部“⚙ 设置”;大屏右上角“⚙ 设置”。每项都写了用途和填写示例;改“主机地址”时“接口地址”会自动跟着改。
