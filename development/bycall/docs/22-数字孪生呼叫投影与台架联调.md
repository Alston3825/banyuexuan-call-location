## 本轮代码

| 文件 | 内容 |
| --- | --- |
| host/bycall/core/twin_calls.py | `bycall.call.v1` 全量呼叫投影：进行中 + 60 秒内结束；source_epoch/sequence/revision；无语音、转写、自由文字 |
| host/bycall/api/app.py | `GET /integration/twin/calls`，复用 `BYCALL_TWIN_KEY` 只读鉴权（未配置 503，错误 401），no-store |

| host/tools/twin_bench.py、twin_bench_store.json | 台架联调脚本（扮演手表/平板，经 MQTT→主机→网关核对 T1–T9）与虚构 24F 台架配置 |

呼叫项字段：call_id、version、room、floor、kind、service_code、label、priority、state（pending/claimed/arrived/completed/cancelled）、owner_staff、owner_name、requester_staff（仅员工求助）、created_at、claimed_at、arrived_at、ended_at、transfer_pending、transferred。“到场/完成”只以主机事件为准，3D 不得凭人物区域推断。主机的超时升级派单不产生事件，投影里没有“已升级”字段；转交用 transferred/transfer_pending 表示。

## 台架联调结果

环境：云端容器，本机 mosquitto + 主机进程（`python -m bycall.main`，台架配置）+ 数字孪生网关（另一仓库 twin-gateway/server.py）+ 无头 Chromium（SwiftShader 软件渲染）。全部为虚构数据。

## 已知限制

- 软件渲染下一帧 3D 需要数秒，会让页面超过 8 秒没处理新数据而显示“连接中断”。这是正确的保护行为，但说明 N150 上必须实测帧率（T10）；页面新增 `?fps=N` 可限制绘制帧率。
- 信标编号 24-1～24-4 沿用数字孪生仓库的候选清单，现场未写入信标，只用于台架。
- 未构建 Docker 镜像、未发布、未配置现场只读密钥。

## 2026-11-22 网关容器化与 3D 屏自启（数字孪生仓库 twin-gateway/deploy）

网关在 N150 上以独立 compose 项目 bycall-twin 运行：复用主机镜像、host 网络只监听 127.0.0.1:8300、只读根文件系统、nobody 用户，只读密钥只在网关 `.env`。主机端口绑定在 BIND_IP 上，所以网关 `BYCALL_HOST_URL` 要填主机局域网固定 IP。3D 屏由 `setup-twin-screen.sh` 设为开机自启，用独立浏览器配置在非主屏全屏打开 `/?mode=live`。

云端用 python:3.11-slim 容器代替主机镜像，接台架主机重跑 T1–T9 全部通过（结果见项目文件 台架T1-T9结果-网关容器.json）。仍需现场：Wayland 下两个全屏窗口是否各落一屏、护士站大屏是否固定在主屏、N150 核显 3D 帧率（T10）。

## 2026-11-22 双屏硬件与显示方式

主机为康耐信 N150 加强版（16G DDR5、512G、HDMI + DP 双原生输出）。用户决定：护士站大屏接 HDMI 作主屏，3D 屏接 DP，扩展模式。数字孪生仓库 `twin-gateway/deploy/setup-twin-screen.sh` 负责 X11 会话、双屏排列（dual-layout.sh）、护士站浏览器固定主屏、3D 固定 DP；它会改写本仓库 setup-kiosk.sh 生成的 `~/.local/bin/bycall-station.sh`（加排列调用和 `--window-position=0,0`，带标记可取消），所以重新运行 setup-kiosk.sh 后要再运行一次它。3D 屏默认 1080p、30 帧、像素比 1、硬阴影，现场用 `TWIN_STATS=1` 读实际帧率做 T10。
