# Ubuntu N100：主机服务与同机大屏安装设置

整理：2026-11-16（America/Los_Angeles）。适用于用户已确认的 Ubuntu N100，显示器直接接在 N100 上。本轮仅提供资料和启动脚本，未远程安装、发布或改动真实设备。

## 1. 大屏在哪里

大屏是主机服务附带的网页，不是 Android APK，不单独双击 station.html 运行。

- 页面源文件：host/bycall/api/station.html。
- 整套主机安装内容：host/ 目录（Python 服务、MQTT、数据库及部署配置）。
- 启动后在 N100 的浏览器打开 `http://N100固定IP:8100/station`。
- 本机和其他局域网终端均可访问同一个主机地址；同机不需要第二台电脑。

N100 要有 Ubuntu 图形桌面和浏览器。如果显示器目前只有文字终端，说明尚无可用桌面环境；先安排桌面环境，不要误以为后端网页不能运行，更不要因此直接重装或清盘。以下全屏/自动登录步骤在 Ubuntu 桌面用户会话内操作。

**BIND_IP 设为局域网 IP 时，Docker 只监听该地址，所以同一台 N100 也请用该 IP，不要直接假定 127.0.0.1 可用。**

## 2. 安装前准备

- N100 用网线接店内路由器/交换机；在路由器做 DHCP 地址保留，例如 `192.168.1.10`，以实际门店网段为准。
- 平板、手表接同一局域网，设备能访问 N100；如 WiFi 开启客户端隔离，要由网络人员保证设备到主机的连通。
- 首次构建需要联网下载依赖和 Docker 镜像；压缩包是源码安装资料，不是已经构建好的离线镜像，也不包含语音识别模型。
- 此指南用于全新/独立测试安装。**若 /opt/bycall/host 已有程序、.env 或业务数据库，不执行下面的覆盖复制、重新初始化配置流程；先保留旧配置与数据，另按升级流程处理。**

## 3. 把主机目录复制到 N100

把资料包通过 U 盘或局域网传到 N100，解压后在“含 host 文件夹”的目录打开终端：

```sh
sudo mkdir -p /opt/bycall
sudo cp -a host /opt/bycall/
cd /opt/bycall/host
```

如果 Docker 和 Compose 已安装，跳过安装软件，只检查版本。若尚未安装，在本项目面向的 Ubuntu 24.04 环境执行：

```sh
sudo apt update
sudo apt install -y docker.io docker-compose-v2 curl
sudo systemctl enable --now docker
sudo docker compose version
```

项目原 deploy/install-ubuntu.sh 会重置 ufw 规则，不应在已有业务网络配置的机器上不加区分地执行。本同机指南不要求运行它。系统时区和时间同步请按原 docs/09 核对；不要在有业务的主机上随意改时钟。

## 4. 建立配置和构建镜像

仅首次安装创建 .env：

```sh
cd /opt/bycall/host
sudo cp .env.example .env
sudo chmod 600 .env
sudo mkdir -p config mosquitto/auth
sudo cp bycall/custom/banyuexuan/demo_pilot.json config/store.json
sudo nano config/store.json
```

store.json 初始为虚构两房演示数据。可先用于独立测试，之后逐项登记实际门店 ID、房间/平板号、员工/手表设备号、信标、班组和排班。手表 SN 必须与 MQTT 设备号相同；备用表写入顶层 watches 字典，不能只在大屏空位里填写。详细结构见 docs/11。不能直接用演示护士或假信标作为真实门店台账。

编辑 .env：

```sh
sudo nano .env
```

至少填写以下字段（所有尖括号占位符必须替换，不可照抄当真实值）：

```dotenv
BIND_IP=192.168.1.10
BYCALL_CONFIG=/config/store.json
BYCALL_API_KEY=<自行生成的高强度随机主机密钥>
MQ_CONF=mosquitto.prod.conf
MQTT_USER=host
MQTT_PASSWORD=
BACKUP_PATH=./data/backups
BYCALL_WATCH_ADMINS='{"<另一串独立随机令牌>":"护士站管理员"}'
```

- IP 改为 N100 实际固定 IP。
- 主机密钥用于护士站大屏；换表管理员令牌必须独立，普通设备密钥不能执行换表。
- 首次测试可先用 ./data/backups，同盘只能用于测试；正式使用按 docs/09 设置独立备份盘和加密云备份。不要在不了解磁盘时执行格式化命令。
- 管理系统凭据未知时保留 MGMT_URL 等为空，先验证本地链路；不要填猜测地址/凭据。

构建当前源码镜像（首次可能耗时较长）：

```sh
sudo docker compose build host
```

## 5. 生成设备账号，填写主机 MQTT 密码

在 /opt/bycall/host 执行，--no-deps 避免账号尚未生成时先启动 Broker：

```sh
sudo docker compose run --rm --no-deps -T -v "$PWD/mosquitto/auth:/out" host python tools/gen_mqtt_auth.py --config /config/store.json --out /out
sudo less mosquitto/auth/credentials.json
```

在 N100 本机查看并记录 host 的密码，以及每个设备号对应的密码；这些是真实秘密，不发聊天、不放源码仓库。然后：

```sh
sudo nano .env
```

把 host 密码填入 MQTT_PASSWORD；平板、手表分别使用自己设备号对应的密码。账号不能互借。后续增加备用表需更新 store.json 并重新生成账号/ACL，工具会保留仍存在设备的原密码。

## 6. 启动与检查

```sh
sudo docker compose up -d
sudo docker compose ps
curl http://192.168.1.10:8100/health
```

把示例 IP 改成实际地址。应看到 host 健康、MQTT 运行，health 返回 ok=true。若失败，先看日志，不重复删除数据库重装：

```sh
sudo docker compose logs --tail 100 host mosquitto
```

软件启动成功还不等于真实 WiFi、设备和班次已验收。正式试点前按 docs/09 做 MQTT ACL 和备份恢复验证；运行数据不会打包在此次安装资料中。

## 7. 打开并设置大屏

在 N100 已有的桌面浏览器输入：

`http://192.168.1.10:8100/station`

进入右上角“⚙ 连接设置”：

1. 主机地址填 `http://192.168.1.10:8100`。
2. API 密钥填 .env 的 BYCALL_API_KEY。
3. 专用护士站可勾选“在本台专用护士站记住密钥”，否则浏览器重开后需要再填写。
4. 保存并连接，核对门店、右侧至少 40 格、实际设备数。
5. 点击“启用声音提醒”。浏览器声音可能需要人工点击，不能把自动全屏当作自动获得声音播放权限。

同一主机的其他入口：

| 路径 | 用途 |
|---|---|
| /watch-admin | 换表、备用池及审计；填独立换表管理员令牌 |
| /backup | 备份设置及状态 |
| /station 右侧“每日统计 / 导出” | 每日在线/离线/未观测查询与 JSON 导出 |

浏览器 F11 可进入/退出普通全屏。也可以从桌面终端运行（把 IP 改成实际值，不要用 sudo 启动浏览器）：

```sh
/opt/bycall/host/deploy/start-station-screen.sh http://192.168.1.10:8100
```

脚本等待 health 后，使用现有 Firefox/Chromium/Chrome 的 kiosk 模式；没有浏览器时会明确报错，不自动安装软件。Kiosk 模式可用 Alt+F4 关闭该浏览器窗口，日常维护也可先用普通浏览器测试。

## 8. 桌面登录后自动显示大屏

主机 Docker 服务由系统开机启动，Compose 服务已设置 unless-stopped。大屏浏览器还需要桌面用户登录；BIOS“来电自启”、Ubuntu 自动登录和桌面自动启动是不同设置。

在实际显示大屏的桌面用户终端操作（不是 root 用户，不要 sudo 写其自启动配置）：

```sh
mkdir -p "$HOME/.config/autostart"
nano "$HOME/.config/autostart/bycall-station.desktop"
```

填写以下内容，替换 IP：

```ini
[Desktop Entry]
Type=Application
Name=伴月轩护士站大屏
Exec=/opt/bycall/host/deploy/start-station-screen.sh http://192.168.1.10:8100
Terminal=false
X-GNOME-Autostart-enabled=true
```

若需要无人值守整机启动，在 Ubuntu 图形“设置 → 用户”中为专用护士站用户设置自动登录；在电源设置里关闭自动挂起/屏幕自动变黑。菜单名称以实际桌面为准。本轮没有替用户修改这些系统设置。注销再登录检查自动启动；真正断电恢复需现场单独验收。

## 9. 手表与客房平板的连接参数

安装配套测试 APK 后，点可见“设置/连接设置”按钮，填写：

- MQTT 主机：192.168.1.10（不带 http://）。
- MQTT 端口：1883。
- API 地址：http://192.168.1.10:8100。
- 门店 ID、设备号：必须和 store.json 一致。
- MQTT 密码：credentials.json 中该设备自己的密码。
- 客房平板另外填写房间 ID、楼层及平板接口密钥；新版腕表无需填写全局 API 密钥，绑定和只读升级令牌由已认证 MQTT 链路下发。

主机建好但未配置/连通设备时，大屏空位或“未观测”是正常状态；40 个位置不代表已有 40 块表在线。换表还需备用表在线、电量/信号达标，完成本地清空回执后才可借出。

## 10. 本轮交付范围

这是源码安装资料和开屏脚本，不含 N100 的已构建 amd64 镜像、不含真实 .env/密码/数据库/客户资料，不是已在真实 N100 上执行过的安装。配套功能已通过 136 项后端回归与两端 debug APK 构建；本机屏幕启动脚本仅完成语法/分支检查，实际 Ubuntu 桌面开机自启与现场安装待验证。已有生产 N100 的升级另按原发布授权处理。
