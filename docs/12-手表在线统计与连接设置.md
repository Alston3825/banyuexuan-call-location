# 手表在线统计与三端连接设置

开发日期：2026-11-15（America/Los_Angeles）；业务报表按 Asia/Shanghai 自然日。仅本地开发和虚构数据验证，未上线、未写入真实数据库。

## 大屏与设置入口

护士站大屏右侧显示所有已登记手表，包含当前绑定表和备用表；至少保留 40 个显示位置，不足的显示“未配置手表”，不虚构在线设备。超过 40 块按实际数量扩展。已在浏览器 1280×720 检查 40 张卡片全部位于右侧可视范围内；大屏 1500px 以上采用 5 列，普通宽屏 4 列；窄屏纵向显示并允许滚动。

每格显示 SN、当前员工/未绑定、电量和状态：

- 绿色 ONLINE：主机收到有效在线消息/心跳。
- 红色 OFFLINE：明确断开或心跳超时，持续显示离线时长（天 + 时:分:秒），每秒更新；重连后恢复绿色，已结束的离线区间留在后台。
- 黄色 UNKNOWN：尚未观测或主机监控中断。未收到首个心跳不能假定一直离线；首次部署之前的历史不会补造。

右侧“每日统计 / 导出”支持日期、手表 SN、员工 ID 条件查询和完整 JSON 明细下载。日期范围上限 31 天，可分月导出。配置表少于 40 块不影响查询；新设备仍须先配置真实 SN/MQTT 身份，不会因屏幕有空位自动注册匿名设备。

三个可见入口：客房平板顶部“⚙ 连接设置”、手表顶部“设置”、护士站顶部“⚙ 连接设置”。平板和手表复用原设备配置表单（主机、门店、设备号、MQTT 密码、API 地址等）和保存后重连逻辑，不再必须长按才能找到。护士站可填写主机 HTTP 地址和 API 密钥；默认密钥仅保留本页会话，可在专用护士站勾选记住。切换到另一主机只跳转地址，密钥不会放到 URL 或自动发送给新主机，抵达后需填写目标主机密钥。

## 持久化与统计口径

新增 watch_presence 保存当前状态与持续起点，watch_presence_intervals 保存起止时刻、状态、门店、SN、员工 ID、绑定 ID、触发原因；presence_observer 保存主机最后观测检查点。SQLite 本地持久化，不依赖浏览器持续打开。

- MQTT 明确断开：以主机收到断开时刻开始离线。
- 静默掉线：沿用 watch_policy.offline_seconds（默认 90 秒），以最后心跳 +阈值为推断离线起点；不能当作物理断网的精确时刻。
- 同一状态的重复心跳/断开不反复建立区间，也不重置离线计时。
- 换绑按操作时刻切分员工和 binding_id，设备连续离线的起点不因员工变化重置；可分别按设备或员工检索。
- 按北京时间零点截断跨日区间，在线/离线/未观测时长独立累计；同一天出现多次绑定会分行，导出保留分段，不抹掉历史。
- 主机重启：最后有效观测检查点之后到恢复有效观测之间记 UNKNOWN，不把主机停机时间算作员工或手表离线。
- 部署前、未登记前没有可靠观测，不追补这些时段。ONLINE 是设备连通性，不等于人员在岗、劳动时间或服务到场；结合班次、人工到场及 BLE 推测分别分析。

## 定位记录供后续分析

locations 新增 store、binding 字段及查询索引；继续保留 staff 和 watch，换人即使停留同一信标也写新归属记录。区域变化立即记录，同一区域每至少 60 秒保留一次实际收到的定位采样；不会把没有定位上报的间隔插值成活动轨迹。现有应用没有检测到任何信标时不发送定位，上报中断需要结合在线/未观测区间判断。

历史 locations 中没有 store/binding 的数据不伪造归属，新接口仅查询本轮带店标识的新数据；需要处理旧数据时另做有依据的迁移方案。

## 接口

均为原护士站 API 密钥认证，只读查询：

| 接口 | 参数 / 返回 |
|---|---|
| GET /station/snapshot | 新增 watches 数组、watch_slots；设备状态、since、elapsed_seconds、last_seen、staff、binding、电量 |
| GET /station/watch-presence | start/end（YYYY-MM-DD，1–31 天）、可选 watch/staff；返回 summary 与 intervals（状态、起止、秒数、归属、原因、是否仍在持续） |
| GET /station/watch-activity | 相同日期/设备/员工筛选；after 为位置行 ID，limit 默认 1000、最多 2000；返回 items、next_after、has_more；按游标取完，不直接截断全量后冒称完整 |

导出的 JSON 含员工、设备和轨迹关联信息，按既有业务数据规则本地保管，不进入源码备份仓库。运行数据表随现有业务数据库备份一起保护；本轮没有创建或导出任何真实员工数据。

## 验证与现场测试

新增 8 项自动化测试：超时精确边界与重连、重复断开不重置、首连前未知、北京时间跨日分割、主机停机未知、换绑员工分割、49 块真实配置条目的完整显示/接口鉴权/参数边界、轨迹绑定及分页。完整回归 136 项通过（原 128 +新增 8）；Android 两端 debug 编译通过。

浏览器使用临时演示容器和 40 块虚构手表验证：12 在线、12 离线、16 未观测；检查最后一格边界仍在容器内，统计页单表查询可见在线/离线累计及区间数。临时容器用完停止，不影响原服务。

现场验收：

1. 安装本轮手表/平板测试 APK；主机更新到配套源码后打开大屏，先验证各端设置按钮、保存参数和重连。
2. 登记真实 SN 和备用池，核对实际设备数与在线数；不要把“40 个位置”误作已连上 40 块设备。
3. 同时测试主动关机/LWT、关 WiFi、AP 断电；记录最后心跳、超时边界，检查离线计时持续；恢复后停止离线计时并保留历史区间。
4. 主机关停后恢复，检查停机段为 UNKNOWN；不可把该段归为工作人员离线。
5. 两位员工换表，核对同一设备的连续离线起点不重置，后台分段员工和 binding_id 正确；定位同一房间换人也要产生新记录。
6. 在北京时间午夜前后模拟断线/恢复，核对每天累计；查询导出与区间时长求和一致。大屏关闭不影响主机记录。
7. 验证 40 格在现场屏幕分辨率、浏览器缩放和字体下都可读；如配置超过 40 表，确认滚动及扩展正常。

本轮未部署到原服务，也未安装/改动真实设备。实际 WiFi 掉线判断、跨 AP、实机 UI 可读性和长时运行均待现场验收。
