# 样机供应商核查与验收

日期：2026-10-26。当前没有已联系厂家、已核验型号或报价。本表用于下一步统一询价与技术筛选，未授权发送给外部人员，也未发生采购。

## 样机范围

2 台全双工客房终端、3—4 块可开发手表、6—10 个可配置 BLE Beacon、1 台本地主机。交换机/AP、PoE、UPS 按现场条件补充。LoRa 暂列可选，不为满足早期 PDF 名称而购买。

## 供应商必须提交的证据

| 类别 | 必问项 | 通过证据 |
|---|---|---|
| 客房终端 | 实体普通/紧急按键、麦克风、扬声器、回声消除、供电、本地语音协议、按键事件与反馈接口 | 在自有局域网按键触发业务并与手表同时双向讲话；可区分“按钮已按”与“平台已收到” |
| 手表 | CPU/系统版本、应用安装签名、SDK、后台/锁屏接收、Wi-Fi、BLE 扫描、音频全双工、震动与声音权限 | 运行我们自己的样例应用，锁屏与省电状态下仍完成提醒、接单、通话、扫描，提供可复现记录 |
| 信标 | 标识配置、功率/间隔、换电池、心跳或电量广播能力、批量配置和安装 | 实测门内外/隔壁/上下层观测数据；不能只提供“米级定位”宣传 |
| LoRa 可选 | 具体频段/型号/合规资料、收发协议、确认重传、去重、加密认证、冲突处理 | 多终端并发与边界覆盖测试；与现有 Wi-Fi 故障时能力分别说明 |
| 开放性 | 完整协议、SDK/示例、开发环境、调试权限、升级与回滚、签名权、版本支持 | 在离开厂家账号/云服务、禁止外网的本地网络中运行 |
| 授权与成本 | 样机/量产单价、SDK/账号/云订阅/定制费用、商业再开发与再分发权、交付周期、MOQ、售后、退换条件 | 书面授权条款和逐项报价，不能仅口头承诺“可二开” |
| 运维 | 凭证注入/轮换、设备唯一身份、批量管理、清洁消毒材料适配、备机 | 实际换绑/撤销旧设备、升级失败恢复；材料和防护等级提供依据 |

仅支持运营商电话、仅支持厂家 App、语音必须经过厂家云、无 BLE 观测接口或无后台可靠运行证明的设备，不能作为首期完整功能候选。可以分部件验证，但须明确缺失能力。

## 样机验收记录模板

每次记录：日期、门店/房间、设备型号/固件、App/服务版本、网络拓扑、电量、测试步骤、原始日志、结果、失败原因、复测记录。耗时用服务端时间和设备单调时钟分别记录，时钟偏差不可当传输延迟。

| 编号 | 场景 | 观察与进入下一阶段条件 |
|---|---|---|
| A01 | A房呼叫，主责锁屏 | 正确手表显示房号/类型并提醒；记录收到、送达、接单耗时和失败数 |
| A02 | A/B房同时呼叫与组员抢单 | 两张独立任务；每张只有一个当前负责人；其他手表显示已接单 |
| A03 | 主责忙碌、离线、无排班、超时 | 按配置支援/升级并在护士站可见；无人匹配也不能丢单 |
| A04 | 紧急呼叫与普通呼叫并发 | 紧急提醒优先且不丢普通任务；多终端收到与接单互斥分别验证 |
| A05 | 全双工语音 | 双方同时讲话、回声、啸叫、延迟、走动漫游；失败仍能处理呼叫任务 |
| A06 | 门内/门外/邻房/上下层 | 人工标记真实位置，统计错房、漏判、未知、切换延迟；BLE 不直接确认到场 |
| A07 | 到场、远程解决、离房取物、转交 | 结案依据清晰；离房不自动完成；全部时间线可追溯 |
| A08 | 08:30/18:00 交班含通话 | 新任务换责任；已接单显式转交；通话不强制断开 |
| A09 | 换表、低电量、整班工作 | 新表继承任务，旧表不能再操作；测完整白/夜班真实扫描、提醒和通话负载 |
| A10 | 断外网、断AP、断跨层、断电 | 分别记录受影响功能、发现时间、人工兜底、恢复时间和补传结果 |
| A11 | 服务重启、重复/乱序/丢失事件 | 已持久化任务恢复，事件去重，序号缺口可发现，不把传输“至少一次”说成天然不重复 |
| A12 | 未授权设备/跨店/旧绑定请求 | 拒绝并审计；不泄露客户、轨迹或语音信息 |

普通提醒 P95≤2 秒来自 V0.1 候选目标，建议同一条件至少做 100 次记录，但次数本身不构成安全或可靠性认证。最终需要运营确认紧急响应、通话质量、定位错房容忍度、允许停机和整班续航门槛。失败用例必须保留，不能仅展示成功视频。

## 技术核验参考

Android 官方后台 BLE 文档说明后台执行与进程生命周期存在约束，因此“Android 手表”不能直接等同于锁屏扫描与提醒可靠：[后台蓝牙通信](https://developer.android.com/develop/connectivity/bluetooth/ble/background)。定位用途所需权限依系统版本和厂商实现核实，不能把不用于定位的声明用于本项目定位业务。

本地 SIP 仍需正确处理信令与音频媒体的地址和网络路径，不能只测网页访问或 ping：[Asterisk 网络与 NAT 配置](https://docs.asterisk.org/Configuration/Channel-Drivers/SIP/Configuring-res_pjsip/Configuring-res_pjsip-to-work-through-NAT/)。此链接用于解释链路约束，不是要求对公网开放端口，也不是已决定采用 Asterisk。
