# 伴月轩智能呼叫定位系统
# 护理师腕表一键换绑功能 —— 开发需求文档

> 文档版本：V1.0
> 交付对象：后端 / 前端 / 手表端开发（可直接交付 Claude Code 编写）
> 适用场景：月子中心护理师在岗期间，腕表电量耗尽或故障，由护士站快速换表，无需跑到对应房间、无需后台人工逐条改配置。

---

## 1. 背景与目标

### 1.1 业务背景
- 系统由 **员工智能手表**、**客房平板**、**楼层主机（N150 工控机）** 三端组成，已跑通通讯。
- 一名护理师同时服务 3~4 个房间，**业务归属以"护理师本人"为核心，不以单个房间为核心**。
- 手表电池有限，在岗中途可能没电，需要护理人员在护士站即可完成换表，尽量缩短脱岗时间。

### 1.2 设计目标
1. **护士站一键换表**：护士站专用平板调出护理师当日班次，扫备用表二维码即可完成替换，全程不超过 1 分钟。
2. **业务数据无缝迁移**：原表绑定的待办事件、未闭环紧急呼叫、服务房间权限、定位归属等，全部自动切到新表，不丢事件、不串人。
3. **支持回绑**：原表充电完成后，可一键切回原表；备用表归还备用池并清空个人数据。
4. **断网可操作**：跨楼层（16 楼 / 24 楼）光纤链路中断时，换表/回绑操作先本地缓存，链路恢复后自动同步，不卡在跨层通信上。
5. **全程留痕**：所有换表、回绑、归还操作写入主机日志，可追溯。

### 1.3 明确排除的方案
- **不采用修改 MAC 地址顶替身份的做法**。改 MAC 只解决网络层身份一致，无法自动同步班次、服务房间、待办事件等业务数据；本方案在**业务层 + 网络层双重同步**，以员工 ID 为主键完成绑定切换。

## 2. 角色与术语

| 术语 | 定义 |
|---|---|
| 护理师 / 员工 | 佩戴腕表上岗的服务人员，业务归属主体。系统内有唯一员工 ID。 |
| 原表 | 护理师当前在岗佩戴的腕表（电量耗尽或故障，待换下）。 |
| 备用表 | 备用池中充满电、已清空个人数据、可随时借出的腕表。 |
| 护士站平板 | 固定放置在护士站的专用终端，登录"换表管理员"账号，执行换表 / 回绑操作。 |
| 备用池 | 后台统一管理的可用备用表清单，含电量、状态、最近校准记录。 |
| 绑定关系 | 员工 ID ↔ 手表 SN（序列号）↔ 班次/服务房间 的当前有效映射。 |

## 3. 数据模型变更要求

### 3.1 员工表（staff）需补充字段
| 字段 | 类型 | 说明 |
|---|---|---|
| current_watch_sn | string | 当前绑定手表 SN；未佩戴为空。 |
| current_bind_id | string | 当前有效绑定记录 ID。 |
| today_schedule_id | string | 当日班次 ID（关联班次表）。 |
| served_rooms | array<string> | 本班次关联的服务房间号列表（3~4 个，随班次自动带出）。 |

### 3.2 手表表（watch）需补充字段
| 字段 | 类型 | 说明 |
|---|---|---|
| watch_sn | string | 手表唯一序列号（主键，二维码即编码该 SN）。 |
| watch_mac | string | MAC 地址，仅作网络识别记录，**不参与身份顶替**。 |
| status | enum | `IDLE`（备用池空闲）/ `BORROWED`（已借出在岗）/ `CHARGING`（待充电）/ `FAULT`（故障）/ `RESETTING`（重置中）。 |
| battery_level | int | 当前电量百分比。 |
| bound_staff_id | string | 当前绑定员工 ID；空闲表为空。 |
| last_bind_time | datetime | 最近一次绑定时间。 |
| last_reset_time | datetime | 最近一次清空个人数据时间。 |
| note | string | 备注（故障原因、维修记录等）。 |

### 3.3 绑定关系表（watch_binding）—— 历史留痕
| 字段 | 说明 |
|---|---|
| bind_id | 绑定记录 ID。 |
| staff_id | 员工 ID。 |
| watch_sn | 手表 SN。 |
| schedule_id | 班次 ID。 |
| action_type | `BIND`（正常领用）/ `SWAP_OUT`（换出原表）/ `SWAP_IN`（换入备用表）/ `ROLLBACK`（回绑原表）/ `RELEASE`（归还备用池）。 |
| prev_watch_sn | 操作前一块表 SN（换入/回绑时记录）。 |
| operator_id | 操作人（护士站账号 / 员工本人）。 |
| operate_time | 操作时间戳。 |
| operate_source | 操作入口：`NURSE_STATION`（护士站平板）/ `WATCH_BUTTON`（手表端一键归位）。 |

### 3.4 事件 / 待办表需关联员工 ID
- 所有呼叫事件、定位记录、待办任务均以 **staff_id** 为归属主键，手表 SN 仅作为上报通道标识。
- 换表时按 staff_id 迁移进行中的事件，避免因换 SN 导致事件挂空。

### 3.5 操作日志表（operation_log）
| 字段 | 说明 |
|---|---|
| log_id | 日志 ID。 |
| staff_id | 涉及员工。 |
| watch_sn_from / watch_sn_to | 操作前后手表 SN。 |
| action_type | 同 3.3。 |
| operator_id / operator_name | 操作人及姓名。 |
| operate_time | 时间戳。 |
| operate_source | 入口来源。 |
| detail | 操作摘要（含同步事件条数、服务房间列表等）。 |
| sync_status | `SYNCED` / `LOCAL_PENDING`（本地缓存待同步）。 |

## 4. 手表状态机

```
                 护士站借出 / 换入
   IDLE ────────────────────────────► BORROWED
    ▲                                   │
    │  RELEASE（归还备用池，清空数据）     │ 电量耗尽 / 故障
    │                                   ▼
   RESETTING ◄────────────────────  CHARGING / FAULT
    │                                   ▲
    └──────── 重置完成、电量达标 ────────┘

   BORROWED（备用表在岗） ──ROLLBACK──► 原表回绑，备用表 → RESETTING
```

- `IDLE`：在备用池，电量 ≥ 阈值（建议 ≥ 80%），个人数据已清空，可借出。
- `BORROWED`：在岗佩戴中，绑定某员工。
- `CHARGING`：换下后待充电。
- `FAULT`：故障待检修，不可借出。
- `RESETTING`：归还后正在清空本地缓存与个人信息，完成后转 `IDLE`。

## 5. 核心业务流程

### 5.1 流程一：护士站换表（原表没电 / 故障）

**前置条件**
- 护士站平板已登录"换表管理员"账号，具备换表权限。
- 备用池中存在状态为 `IDLE`、电量达标的备用表。

**操作步骤**
1. 护理师到达护士站，告知员工身份（刷卡 / 搜姓名 / 扫员工工牌二维码，三选一，以后续实现为准）。
2. 平板调出该员工**当日班次**页面，页面展示：
   - 员工姓名、工号、当前在岗状态；
   - 当前佩戴手表 SN、当前电量；
   - 本班次服务房间列表（3~4 个）；
   - 未闭环事件数量（待处理呼叫、进行中待办）。
3. 护士在备用池中选一块备用表，用平板扫码枪 / 摄像头扫描备用表表身二维码（编码 watch_sn）。
4. 系统先做**借出前校验**（见第 7 节），校验通过后页面展示"确认换表"摘要：
   - 员工：XXX；
   - 原表：SN-xxxx（电量 x%，状态：低电/故障）；
   - 新表：SN-yyyy（电量 x%）；
   - 将同步：服务房间 N 个、未闭环事件 M 条。
5. 点击"**确认替换绑定**"，系统执行：
   - 生成 `SWAP_IN` 绑定记录：备用表绑定到该员工；
   - 员工 `current_watch_sn` 更新为新表 SN；
   - 原表状态置为 `CHARGING`（低电）或 `FAULT`（故障），解除在岗绑定；
   - 按员工 ID 迁移未闭环事件、待办、定位归属、服务房间权限到新表；
   - 写入操作日志（`SWAP_OUT` + `SWAP_IN` 两条，或合并为一条换表记录，实现时定）。
6. 新表上线后自动拉取员工班次、服务房间列表、个人配置；平板页面提示"换表成功，可上岗"。
7. 护理师佩戴新表离开，原表交由护士站放置充电/检修。

**关键约束**
- 原表已关机、扫不出码不影响流程：流程以员工身份为入口，**不需要扫原表二维码**。
- 换表过程中若新表校验不通过（电量不足、状态非 IDLE、已绑定他人），禁止提交，页面给出明确原因。

### 5.2 流程二：一键回绑（原表充好电后换回）

**触发方式（双向均可）**
- **方式 A：手表端触发**。充好电的原表开机联网后，在手表快捷菜单提供"**一键归位**"按键；当前佩戴备用表的手表快捷菜单同样提供"**一键归位**"按键。任一方按下，即发起回绑请求。
- **方式 B：护士站触发**。护士站平板在员工班次页，对当前佩戴备用表（watch_sn 标记为备用表来源）的员工，提供"**切回原表**"按钮。

**回绑执行步骤**
1. 系统校验：原表已充电达标、状态为 `IDLE` 或 `CHARGING` 满电、未绑定他人。
2. 生成 `ROLLBACK` 绑定记录：原表重新绑定该员工；备用表解除绑定。
3. 员工 `current_watch_sn` 切回原表；进行中事件、待办、服务房间权限按员工 ID 同步回原表。
4. 备用表状态转 `RESETTING`，执行本地数据清空（见 5.3）。
5. 写入操作日志（`ROLLBACK` + `RELEASE`）。
6. 原表上线后拉取最新班次与事件；页面/手表提示"已切回原表"。

**回绑确认提示**
- 若当前备用表仍有未闭环事件，回绑前提示护士站/员工确认事件已迁移，避免遗漏。

### 5.3 流程三：备用表归还重置（清空为空白可复用状态）

触发时机：回绑完成后、或备用表直接收回不再借出时。

重置内容：
1. 解除与员工的绑定关系，`bound_staff_id` 置空；
2. 清空手表本地缓存：员工信息、班次、服务房间列表、待办、历史呼叫记录、定位缓存、登录态/令牌；
3. 恢复手表默认配置（音量、表盘等可按品牌默认值）；
4. 电量记录更新，状态转 `IDLE`，回到备用池可被再次借出；
5. 写入 `RELEASE` 日志，记录 `last_reset_time`。

> 安全要求：重置必须在手表本地完成擦除；后台同时清除该 SN 上残留的员工授权信息，防止下一位佩戴者读到上一位员工数据。

## 6. 数据同步范围（换表 / 回绑时必须迁移）

换绑操作执行时，系统按 **staff_id** 自动把以下内容从旧表上下文迁移到新表上下文：

| 类别 | 具体内容 |
|---|---|
| 身份与权限 | 员工身份、岗位角色、可操作功能权限、可呼叫/查看的房间范围。 |
| 班次信息 | 当日班次 ID、班次时间段、服务房间列表（3~4 个）。 |
| 未闭环事件 | 待处理紧急呼叫、进行中待办、未完成工单（含事件时间、房间号、状态）。 |
| 定位归属 | 后续定位记录归属到该员工；历史定位记录按员工 ID 保留可查。 |
| 业务配置 | 手表端个人偏好、提醒规则、关联平板/房间配对信息。 |
| 网络会话 | 新表重新建立与主机、平板、后端的会话；旧表会话在换出后失效。 |

**不迁移的内容**：旧表本地缓存的历史日志（归还时按 5.3 清空）、与旧表硬件绑定的故障记录（保留在手表档案中备查）。

## 7. 借出前校验与电量预检

### 7.1 备用表借出校验（护士站提交前）
- 手表状态必须为 `IDLE`；
- 电量 ≥ 借出阈值（建议默认 80%，可配置）；
- 未绑定任何员工；
- 不在 `FAULT` / `RESETTING` 状态；
- 手表可联网（WiFi 可连通主机），信号强度满足上岗要求。

### 7.2 备用表电量预警
- 备用池列表对每块备用表展示实时电量；
- 电量低于阈值的备用表置灰，不可选，并标注"电量不足，请先充电"；
- 护士站平板提供"备用表低电量"汇总提醒（如备用池中可用表少于 N 块、或多块表电量偏低时弹窗/提示）；
- 在岗手表低电量预警逻辑保持现有规则不变，临近阈值时提示员工到护士站换表。

### 7.3 校验失败提示
所有校验不通过场景需在页面明确展示原因（非 IDLE、电量不足、已绑定他人、离线等），禁止绕过校验强制绑定。

## 8. 跨楼层断网本地缓存与恢复同步

**背景**：16 楼与 24 楼主机通过光纤链路互联，链路可能中断；换表/回绑操作不能因跨层通信失败而卡死。

### 8.1 离线可操作
- 护士站平板与本楼层主机通讯正常时，即使跨楼层链路中断，仍可在本地完成换表/回绑操作。
- 操作先写入本楼层主机本地持久化队列，标记 `sync_status = LOCAL_PENDING`。

### 8.2 缓存内容
- 绑定关系变更、员工当前手表 SN、事件归属切换、操作日志记录，均纳入本地待同步队列。

### 8.3 链路恢复后自动同步
- 链路恢复后，主机按时间顺序把本地待同步记录批量推送到对端楼层/中心数据库；
- 同步成功后更新 `sync_status = SYNCED`；
- 若存在冲突（如两端同时对同一员工做了换绑），按时间戳 + 操作类型冲突策略处理，冲突记录进入异常列表由管理员人工确认（冲突策略待产品确认，见第 12 节）。

### 8.4 提示与兜底
- 断网期间护士站页面标注"当前为离线操作，数据待链路恢复后同步"；
- 长时间未同步的待同步记录在后台可见并告警。

## 9. 权限与入口

### 9.1 护士站平板
- 使用专用"换表管理员"账号登录，独立入口（可在现有平板 App 内开启专属"护士站换表"页面，不必单独开发全新应用）。
- 权限范围：查看员工班次、查看备用池、执行换表、执行回绑、查看操作日志。
- 不可修改员工基础信息、不可删除历史日志。

### 9.2 手表端
- 仅提供"一键归位"触发按键，不提供员工切换、换绑他人等管理功能。

### 9.3 后台管理端
- 可查看全部绑定记录、操作日志、备用池状态；可手动重置故障表、调整备用表状态。

## 10. 异常与边界处理

| 场景 | 处理要求 |
|---|---|
| 原表彻底损坏、无法开机 | 不影响换表流程，按员工身份直接换入备用表；原表标记 `FAULT` 归档。 |
| 换表时新表扫码后离线 | 禁止绑定，提示"手表离线，请检查网络后重试"。 |
| 同一员工被重复提交换表 | 以最后一次有效操作为准；重复请求需幂等，避免重复生成绑定记录。 |
| 备用表误绑定后立即撤回 | 后台/护士站支持当日内撤销上一次换绑（权限受限，写日志）。 |
| 员工中途下班 / 交接班 | 走正常交接班归还流程，手表解除绑定进入 `CHARGING`/`IDLE`，不适用回绑逻辑。 |
| 事件迁移时出现进行中紧急呼叫 | 优先迁移并在新表/平板强提醒，确保护理师在岗期间不遗漏。 |
| 跨楼层链路长时间中断 | 本地队列持久化不丢失；恢复后按序同步，冲突进异常列表。 |

## 11. 验收标准（功能完成判定）

1. 护士站输入员工身份后，能正确带出当日班次、服务房间列表、当前手表与未闭环事件数。
2. 扫备用表二维码，校验通过后一键完成换表；新表 1 分钟内上线并看到班次与服务房间。
3. 换表后原表解除绑定并进入待充电/故障状态；未闭环事件全部出现在新表上下文，无丢失、无串人。
4. 原表充满电后，可从手表端或护士站一键回绑；回绑后备用表自动清空个人数据并回到备用池。
5. 备用池低电量表不可被选中；可用备用表不足时护士站有提醒。
6. 跨楼层链路中断时换表/回绑可本地操作；链路恢复后数据自动同步，日志状态更新为已同步。
7. 每一次换出、换入、回绑、归还、重置均有日志记录，包含操作人、时间、前后手表 SN、员工、同步状态。
8. 不依赖修改 MAC 地址完成身份切换；MAC 仅作网络识别记录。

## 12. 待产品 / 业务确认事项

1. 借出电量阈值默认值（建议 80%）、备用池最低可用数量提醒阈值。
2. 员工身份识别方式：工牌二维码 / 刷卡 / 姓名搜索，优先实现哪一种。
3. 跨楼层同步冲突时的裁决策略（时间戳优先 / 中心端优先 / 人工确认）。
4. 手表端"一键归位"是实体按键还是屏幕快捷键；是否需要二次确认防误触。
5. 换表操作是否需要护士站账号二次确认（密码/指纹）。
6. 历史定位与事件记录在报表中按员工展示还是按手表 SN 展示（建议按员工，SN 作为辅助字段）。
