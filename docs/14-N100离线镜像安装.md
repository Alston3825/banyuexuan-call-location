离线方案绕过 N100 对 Docker Hub/PyPI 的下载需求，不等于已经修复该机器的外网、DNS 或代理。

## 用户下一步：只导入，暂不启动

1. 在能下载本地附件的电脑取得完整压缩包，通过 U 盘或局域网传到 N100。
2. 在 N100 普通桌面用户下解压；进入 `banyuexuan-n100-offline-20261116` 文件夹，应能看到 `import-images.sh`、`images-linux-amd64.tar`、`IMAGES.sha256` 和 `host` 等。
3. 在该文件夹空白处右键“在终端打开”，执行：

```sh

```

脚本检查 x86_64、镜像校验和、专用镜像架构；向现有 /opt/bycall/host 复制离线 Compose 覆盖文件，校验 Compose 结构。若已有不同覆盖配置或已有运行服务，会暂停避免覆盖；不要删除旧配置绕过检查。它不启动服务，不修改 .env、账号或数据库，不安装依赖，也不改网络设置。

完成后应显示“离线镜像已导入，配置校验通过”。把末尾输出反馈给开发者；其中不需要任何真实密码。

## 后续：配置完账号后再启动

导入成功后继续 docs/13 第 4–5 节，**跳过所有 build 命令**。用户 IP 已知，.env 中 BIND_IP 填 192.168.1.108；门店/设备表、主机密钥、独立换表管理员令牌和每台设备密码仍需在 N100 本地配置，不在聊天中传输。

源码和离线覆盖文件准备好后，设备账号生成命令为：

```sh
cd /opt/bycall/host
sudo docker compose run --rm --no-deps --pull never -T -v "$PWD/mosquitto/auth:/out" host python tools/gen_mqtt_auth.py --config /config/store.json --out /out
```

此命令前必须已建立 config/store.json。生成后在本机查看 host 密码，填进 .env 的 MQTT_PASSWORD；每台设备用自己的密码。

全部连接参数确认后，启动使用：

```sh
sudo docker compose up -d --no-build --pull never
sudo docker compose ps
curl http://192.168.1.108:8100/health
```

这样不会构建镜像或联网拉取。浏览器打开 `http://192.168.1.108:8100/station`，填写主机密钥；前端连接设置、开屏脚本和自动启动方法见 docs/13。此处是后续步骤，不代表本轮已经在 N100 启动。
